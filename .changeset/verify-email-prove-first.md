**Proving an e-mail on the application's own proof: `auth.<type>.verifyEmail.proveFirst(user)`.** On a user whose e-mail was never proved, it applies exactly what `magicLink.confirm` and `signInCode.confirm` apply to such an e-mail: in one write it marks the e-mail verified and drops the password and the second factor (active or waiting, with its recovery codes); it revokes every session and spends the reset links and second-factor challenges, before the write and after it; and it sends `user.emailVerified`, then `user.passwordChanged` and `user.secondFactorDisabled` when it dropped them. It answers `{ user, proved: true }`. On an e-mail already proved it does nothing and answers `{ user, proved: false }`. It sends no e-mail, issues no token and counts in neither throttle. An inactive user is `USER_INACTIVE`; a malformed, unknown or other-type id is `NOT_FOUND`, as for `signInProven`; a user written between its read and its write is `VERSION_CONFLICT`; an outage is `STORE_FAILED`. On every type with an e-mail.

`signInProven` proves no e-mail, so an invitation accepted with it alone left a password or a second factor that somebody who signed up with the invited address had set. **Accept an invitation in this order**: `findByEmail` (or `create`), `verifyEmail.proveFirst`, `setPassword` on a type with a password, then `signInProven` — `proveFirst` drops the password and revokes every session, so after `setPassword` it erases the new password, and after `signInProven` it revokes the new session. **Privileged**: call it only after your server verified its own proof of the inbox, on the user that proof names — never with an id a request supplied. `@nxgt/janus`: new type `FirstProof<U>`; three new compile-time refusals (169 in all).

`@nxgt/janus-telemetry`: `verifyEmail.proveFirst` is traced as `janus.<type>.verifyEmail.proveFirst` with the `user.id` it proved, and writes `janus.email.verified` marked `janus.email.proveFirst: true` when it proved — never the address. Needs `@nxgt/janus` 0.22 for the new flow.
